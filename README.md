# bowling-lane-growth-system(第四弾:会員管理・成長支援システム)

スポーツボウリング場運営システムの第四弾。会員一人ひとりの「成長」を支援するための、会員管理・マイギア管理・投球データ蓄積・成長ダッシュボードを実装しています。

### このリポジトリのポイント

- 投球データを**Game/Frame/Shot単位**まで分解し、残りピンパターンまで含めて保存する構成
- 会員本人認証とスタッフ認証を**型レベルで分離**し、なりすましを防止
- 第三弾(店舗運営)のデータモデル設計思想を踏襲しつつ、達成バッジ・レーン管理・メンテナンス管理まで拡張

**Status: Complete**(会員管理・投球データ保存・成長ダッシュボードまで実装、pytest + FastAPI TestClientによるE2Eテスト53件PASS)

このリポジトリは、

- 第一・二弾:予約システム(bowling-lane-reservation-system)
- 第三弾:店舗運営システム(bowling-lane-management-system)

に続くフェーズで、第三弾のスタッフ認証・チェックイン等のデータモデル設計思想を踏襲しています。

# 実装機能(第四弾本体)

## 会員本人認証

会員コード/電話番号+PINでログインする、会員専用の認証を実装しています。スタッフ認証(第三弾のPINログインを踏襲)とは型レベルで完全に分離しており、会員用トークンでスタッフ専用APIにアクセスすることはできません。スタッフ側にはロックアウト機構・管理者権限・初回PIN変更の強制も実装し、初期パスワード運用のリスクに対応しています。

## 会員管理

会員の登録・一覧・検索機能です。フロント業務(受付でのその場登録)とバックオフィス業務(会員リストの管理)の両方から使う想定で設計しています。

## マイギア管理

会員が自分のボール・シューズを登録できるセルフ登録と、スタッフが会員IDを指定して代理登録できる仕組みの両方に対応しています。教室参加者や新規会員の初期登録は、スタッフ代理登録でカバーする想定です。ギアのメンテナンス履歴(オイル抜けなど)もあわせて記録します。

## チェックイン/チェックアウト・複数人セッション

来店時のチェックイン/チェックアウトを管理し、重複チェックインを防止します。アメリカン方式(1組2レーンを複数人で交互に利用する形式)を前提に、複数人が同じセッションに参加する構成にも対応しています。

## 投球データの蓄積(Game / Frame / Shot)

投球記録を**Game(1ゲーム)→Frame(各フレーム)→Shot(各投球)**という粒度まで分解して保存しています。各フレームの残りピンパターンも記録しており、単なるスコアの記録にとどまらず、後続の分析(第五弾のスコアリングシステム)につながるデータ構造にしています。標準的な10フレームスコア計算ロジックも実装済みです。

ギアとゲームの紐付けも行っており、ギアごとの累計投球数をカウントできます。

## 成長ダッシュボード

会員ごとに、平均・最高・最低スコア、ストライク率、スペア率、10番ピン残り率、直近成績をまとめて確認できるダッシュボードです。個人の成長を可視化し、継続利用のモチベーションにつなげる位置づけの機能です。

# 第三弾拡張(Phase 3 Extension)

第四弾の開発と並行して、第三弾(店舗運営システム)側の機能拡張も本リポジトリで行っています。

## 第三弾拡張④:初心者教室修了記録

第三弾(教室運営)とは別アプリ・別DBのため自動連携せず、スタッフが手動で紐付けます。「初心者教室を修了し、一般ボウラーとして利用可能になった」という事実のみを管理し、出席回数・各回の指導内容・コーチによる適性評価は持ちません。詳細は`docs/phase3_extension_class_completion.md`に設計メモを残しています。

## 第三弾拡張③:レーン設定・状態管理 × 達成バッジ・称号

### レーン設定・レーン状態管理(LaneSettings / Lane)

- 総レーン数(`total_lanes`)を設定値として管理(初期値4)
- adminが`total_lanes`を変更すると不足レーン番号を自動生成
- レーン状態:`available` / `maintenance` / `broken`
- レーン用途:`general` / `class` / `competitor`
- チェックイン時のレーン番号は、スタッフが`GET /api/v1/lanes`で当日の空き状況を確認し、手動で指定する運用(4レーン運用ではスタッフが目視で十分判断できるため、自動アサインは現時点では採用していない。将来レーン数が大幅に増えた場合の拡張候補)

### 達成バッジ(AchievementBadge)

- 判定ロジックは`app/services/badge_criteria.py`に分離
- 第四弾単体で完結する条件のみ実装:初投球 / 累計10ゲーム / 累計100ゲーム / ギア登録
- 将来第五弾の指標を使う場合も関数追加だけで拡張可能

### API一式

- `GET/PATCH /api/v1/lanes/settings`
- `GET /api/v1/lanes`
- `PATCH /api/v1/lanes/{lane_number}/status`
- `PATCH /api/v1/lanes/{lane_number}/purpose`
- `POST /api/v1/badges/evaluate/{user_id}`
- `GET /api/v1/badges/user/{user_id}`

### チェックイン仕様

- `lane_number`は引き続き必須(スタッフが手動指定)

## 第三弾拡張①:オイル抜きリマインド(メンテナンス管理)

**リマインダー判定**:normal / alert(30ゲーム以上) / snoozed / disabled

**リマインダー操作**:disable(無効化) / snooze(スヌーズ) / reset(リセット)

**権限**:会員本人のみ操作可能。スタッフは閲覧のみ(操作不可)

**役割**:ギアメンテナンス履歴の基盤であり、ギア状態管理(使用状況・メンテナンス状況)の統合を担います。将来の「メンテナンス通知」「ギア状態ダッシュボード」への発展が可能な設計です。
